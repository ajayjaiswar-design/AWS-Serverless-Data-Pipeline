# AWS Serverless Data Pipeline – CarePlus System

## 1. Project Overview

This project demonstrates an AWS-based serverless data pipeline designed to process Support Logs and Support Tickets generated by the CarePlus System.

CarePlus is an imaginary Business Process Outsourcing (BPO) company that manages customer care operations on behalf of multiple client companies. The project demonstrates how AWS services can be integrated to process raw support data, store analytics-ready datasets, perform SQL-based analysis, and enable business intelligence reporting.

The pipeline uses Amazon S3 for data storage, AWS Lambda and AWS Glue for data processing, Apache Parquet for optimized storage, Amazon Athena for ad-hoc SQL analysis, Amazon Redshift Serverless for data warehousing, and Power BI for reporting and visualization.

The solution supports two primary analytical workflows:

- Ad-hoc Analysis: Query processed data stored in Amazon S3 using Amazon Athena.
- Business Intelligence: Load processed data into Amazon Redshift Serverless and connect Power BI for reporting and visualization.

## 2. Problem Statement

CarePlus is an imaginary BPO company that manages customer support operations for multiple clients. Its operational data is scattered across databases, Excel reports, and dashboards, making it difficult to consolidate information and generate consistent reports.

The lack of a centralized Single Source of Truth (SSOT) leads to manual effort, inconsistent reporting, and delays in decision-making.

This project uses AWS serverless services to process support logs and tickets, store analytics-ready data in Amazon S3, enable SQL analysis through Amazon Athena, and support business intelligence reporting using Amazon Redshift Serverless and Power BI.

## 3. Project Objectives

The primary objectives of this project are:

- Build an end-to-end serverless data pipeline using AWS services.
- Store raw support logs and support tickets in Amazon S3.
- Process support logs using AWS Lambda.
- Process support tickets using AWS Glue.
- Store processed datasets in Apache Parquet format.
- Enable ad-hoc SQL analysis using Amazon Athena.
- Load processed data into Amazon Redshift Serverless for analytical workloads.
- Connect Power BI to Amazon Redshift Serverless for reporting and visualization.
- Demonstrate how data processing, analytical querying, data warehousing, and business intelligence can be integrated into a unified architecture.

## 4. Architecture

!AWS Serverless Data Pipeline Architecture

The architecture separates raw-data storage, data processing, processed-data storage, analytical querying, and business intelligence reporting.

The pipeline branches into two analytical workflows after data processing:

1. SQL Analytics: Amazon S3 → Amazon Athena → Ad-hoc Analysis.
2. Business Intelligence: Amazon S3 → Amazon Redshift Serverless → Power BI.

## 6. Data Pipeline Workflow

### 6.1 Data Source – CarePlus System

The CarePlus System generates two categories of operational data:

- Support Logs: Application or system log data.  
- Support Tickets: Data associated with customer support requests.  

Both datasets follow separate processing workflows before becoming available for analysis.

### 6.2 Data Ingestion – Amazon S3

Raw support logs and support tickets are ingested into Amazon S3 and stored in their respective raw-data locations.

The raw layer preserves the source data before processing and transformation.

**Data flow:**

`CarePlus System → Amazon S3 (Raw Data)`

### 6.3 Data Processing and Transformation

The pipeline uses AWS Lambda and AWS Glue to process the two categories of support data.

#### A. Support Logs – AWS Lambda

AWS Lambda processes the raw support log data stored in Amazon S3.

**Workflow:**

1. Raw support logs are stored in Amazon S3.
2. AWS Lambda executes the log-processing logic.
3. The processed support logs are written back to Amazon S3.

**Data flow:**

`Amazon S3 (Raw Support Logs) → AWS Lambda → Amazon S3 (Processed Support Logs)`

AWS Lambda provides a serverless execution environment for processing log data without requiring the management of dedicated servers.

#### B. Support Tickets – AWS Glue

AWS Glue processes the raw support ticket data stored in Amazon S3.

**Workflow:**

1. Raw support ticket data is stored in Amazon S3.
2. AWS Glue executes the ticket-processing and transformation logic.
3. The processed support tickets are written back to Amazon S3.

**Data flow:**

`Amazon S3 (Raw Support Tickets) → AWS Glue → Amazon S3 (Processed Support Tickets)`

AWS Glue provides a managed data-processing environment for transforming datasets and preparing them for analytical workloads.

### 6.4 Processed Data Storage – Apache Parquet

After processing, support logs and support tickets are stored in Amazon S3 in Apache Parquet format.

Parquet is a columnar storage format well suited to analytical workloads because it supports efficient column-based data access and compression.

The processed-data layer provides a consistent source for downstream SQL analysis and data warehousing.

**Data flow:**

`AWS Lambda / AWS Glue → Amazon S3 (Processed Data in Parquet Format)`

### 6.5 Ad-hoc SQL Analysis – Amazon Athena

Amazon Athena enables ad-hoc SQL queries against processed datasets stored in Amazon S3.

This allows analysts to explore support data without first loading it into a separate database or data warehouse.

**Workflow:**

1. Processed support logs and support tickets are stored in Amazon S3.
2. The datasets are made available for querying through appropriately configured Athena tables.
3. SQL queries are executed against the processed data.
4. Query results are used for ad-hoc analysis and exploration.

**Data flow:**

`Amazon S3 (Processed Parquet Data) → Amazon Athena → Ad-hoc SQL Analysis`

### 6.6 Data Warehousing – Amazon Redshift Serverless

Amazon Redshift Serverless serves as the analytical data warehouse for the business intelligence workflow.

Processed support logs and support tickets are made available from Amazon S3 and loaded into Redshift for centralized analytical querying and reporting.

**Workflow:**

1. Processed data is stored in Amazon S3.
2. The data is loaded into Amazon Redshift Serverless.
3. The warehouse provides a centralized location for analytical queries and reporting.
4. The resulting datasets can be accessed by Power BI.

**Data flow:**

`Amazon S3 (Processed Data) → Amazon Redshift Serverless`

The specific loading mechanism, warehouse schema, and refresh strategy depend on the implementation and are not specified in the supplied architecture.

### 6.7 Business Intelligence and Visualization – Power BI

Power BI connects to Amazon Redshift Serverless to support reporting and business intelligence.

Data available in the warehouse can be used to develop reports and dashboards that help analyze support-related information and operational performance.

**Workflow:**

1. Connect Power BI to Amazon Redshift Serverless.
2. Access the relevant datasets and analytical queries.
3. Develop reports and dashboards.
4. Visualize support-related information for business analysis.

**Data flow:**

`Amazon Redshift Serverless → Power BI → Reports and Dashboards`

## 7. End-to-End Data Flow

The complete pipeline follows this sequence:

1. The CarePlus System generates support logs and support tickets.
2. Raw datasets are ingested into Amazon S3.
3. AWS Lambda processes support logs, while AWS Glue processes support tickets.
4. Processed datasets are stored in Amazon S3 in Apache Parquet format.
5. Amazon Athena queries the processed datasets for ad-hoc SQL analysis.
6. The processed data also feeds Amazon Redshift Serverless for data warehousing.
7. Power BI connects to Amazon Redshift Serverless to build reports and dashboards.

### Pipeline Summary

**Data ingestion and processing:**

`CarePlus System → Amazon S3 (Raw) → AWS Lambda / AWS Glue → Amazon S3 (Processed – Parquet)`

**Analytical workflow 1 – SQL Analytics:**

`Amazon S3 → Amazon Athena → Ad-hoc SQL Analysis`

**Analytical workflow 2 – Business Intelligence:**

`Amazon S3 → Amazon Redshift Serverless → Power BI → Reports and Dashboards`
