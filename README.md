# AWS Serverless Data Pipeline – CarePlus System

## 1. Project Overview

This project demonstrates an AWS-based serverless data pipeline designed to process Support Logs and Support Tickets generated by the CarePlus System.

CarePlus is an imaginary Business Process Outsourcing (BPO) company that manages customer care operations on behalf of multiple client companies. The project demonstrates how AWS services can be integrated to process raw support data, store analytics-ready datasets, perform SQL-based analysis, and enable business intelligence reporting.

The pipeline uses Amazon S3 for data storage, AWS Lambda and AWS Glue for data processing, Apache Parquet for optimized storage, Amazon Athena for ad-hoc SQL analysis, Amazon Redshift Serverless for data warehousing, and Power BI for reporting and visualization.

The solution supports two primary analytical workflows:

- **Ad-hoc Analysis:** Query processed data stored in Amazon S3 using Amazon Athena.
- **Business Intelligence:** Load processed data into Amazon Redshift Serverless and connect Power BI for reporting and visualization.

## 2. Problem Statement

CarePlus is an imaginary BPO company that manages customer support operations for multiple clients. Its operational data is scattered across databases, Excel reports, and dashboards, making it difficult to consolidate information and generate consistent reports.

The lack of a centralized Single Source of Truth (SSOT) leads to manual effort, inconsistent reporting, and delays in decision-making.

This project uses AWS serverless services to process support logs and tickets, store analytics-ready data in Amazon S3, enable SQL analysis through Amazon Athena, and support business intelligence reporting using Amazon Redshift Serverless and Power BI.

## 3. Project Objectives

The primary objectives of this project are:

- Build an end-to-end serverless data pipeline using AWS services.
- Store raw support logs and support tickets in Amazon S3.
- Process support logs using AWS Lambda.
- Process support tickets using AWS Glue.
- Store processed datasets in Apache Parquet format.
- Enable ad-hoc SQL analysis using Amazon Athena.
- Load processed data into Amazon Redshift Serverless for analytical workloads.
- Connect Power BI to Amazon Redshift Serverless for reporting and visualization.
- Demonstrate how data processing, analytical querying, data warehousing, and business intelligence can be integrated into a unified architecture.

## 6. Data Pipeline Workflow

### 6.1 Data Source – CarePlus System

The CarePlus System generates two categories of operational data:

- **Support Logs:** Application or system log data.  
- **Support Tickets:** Data associated with customer support requests.  

Both datasets follow separate processing workflows before becoming available for analysis.

### 6.2 Data Ingestion – Amazon S3

An Amazon S3 bucket named careplus_ds was created to store the raw and processed data generated by the CarePlus System.

The bucket is organized into two main prefixes: support-logs/ and support-tickets/. Each prefix contains two sub-prefixes, raw/ and processed/, to logically separate the original data from the transformed output.

- **Raw:** Stores the original support logs and support ticket data before processing.
- **Processed:** Stores the transformed data after processing by AWS Lambda and AWS Glue.

**S3 bucket structure:**

```
careplus_ds/
├── support-logs/
│   ├── raw/
│   └── processed/
│
└── support-tickets/
    ├── raw/
    └── processed/
```

**Data flow:**

`Support Logs: CarePlus System → Amazon S3 (support-logs/raw/)`  
`Support Tickets: CarePlus System → Amazon S3 (support-tickets/raw/)`  

The raw data is subsequently processed by AWS Lambda for support logs and AWS Glue for support tickets. The resulting datasets are stored under their respective processed/ prefixes in Amazon S3.

### 6.3 Data Processing, Transformation, and Storage

Amazon S3 event notifications are configured to automatically trigger the respective processing workflows whenever new files are uploaded to the raw-data prefixes. This event-driven approach eliminates the need to manually initiate data processing.

#### A. Support Logs – AWS Lambda

An S3 event notification is configured for the *support-logs/raw/* prefix. Whenever a new file is uploaded to this location, it triggers the Lambda function *trigger_automate_logs_etl*.

The Lambda function executes the data transformation logic and stores the transformed output in Apache Parquet format under the *support-logs/processed/* prefix in the same S3 bucket.

**Workflow:**

1. Raw support log files are uploaded to Amazon S3.
2. The S3 event notification triggers *trigger_automate_logs_etl*.
3. The Lambda function processes and transforms the input data.
4. The transformed data is stored in Parquet format in the processed-data prefix.

**Data flow:**

`Amazon S3 (support-logs/raw/) → S3 Event Notification (trigger_automate_logs_etl) → AWS Lambda (automate_support_log_ETL) → Amazon S3 (support-logs/processed/ – Parquet)`

#### B. Support Tickets – AWS Lambda and AWS Glue

An S3 event notification named *trigger_automate_tickets_etl* is configured to initiate the support ticket processing workflow whenever a new file is uploaded to the *support-tickets/raw/* prefix.

The event triggers the Lambda function *automate_support_tickets_ETL*, which invokes the AWS Glue job *Automate_ETL_support_tickets*. The Glue job performs the required data transformation and stores the processed support ticket data in Apache Parquet format under the *support-tickets/processed/* prefix in the same S3 bucket.

**Workflow:**

1. Raw support ticket files are uploaded to *support-tickets/raw/* in Amazon S3.
2. The S3 event notification *trigger_automate_tickets_etl* triggers the Lambda function *automate_support_tickets_ETL*.
3. The Lambda function invokes the AWS Glue job *Automate_ETL_support_tickets*.
4. The Glue job processes and transforms the support ticket data.
5. The transformed data is stored in Parquet format under *support-tickets/processed/*.

**Data flow:**

`Amazon S3 (support-tickets/raw/) → S3 Event Notification (trigger_automate_tickets_etl) → AWS Lambda (automate_support_tickets_ETL) → AWS Glue Job (Automate_ETL_support_tickets) → Amazon S3 (support-tickets/processed/ – Parquet)`

**Processing Summary**  
Both workflows use an event-driven approach to automatically process newly uploaded files and store the transformed datasets in Parquet format. These processed datasets are then available for downstream analysis using Amazon Athena and for loading into Amazon Redshift Serverless.

**S3 output structure:**

```
careplus_ds/
├── support-logs/
│   ├── raw/
│   └── processed/
│       └── *.parquet
│
└── support-tickets/
    ├── raw/
    └── processed/
        └── *.parquet
```

### 6.4 Ad-hoc SQL Analysis – Amazon Athena

Amazon Athena is used to query the processed support logs and support tickets stored in Amazon S3. AWS Glue crawlers discover the processed datasets, infer their schemas, and create tables in the AwsDataCatalog for querying through Athena.

A database named careplus_db was created in Amazon Athena to organize the cataloged support datasets. The following AWS Glue crawlers populate this database with metadata for the processed data:

- **crawl_support_logs:** Crawls *support-logs/processed/* and creates the Athena table *support_logs_processed*.
- **crawl_support_tickets:** Crawls *support-tickets/processed/* and creates the Athena table *support_tickets_processed*.

Once the crawlers complete successfully, the cataloged tables can be queried using SQL in Amazon Athena. Athena executes queries directly against the underlying S3 data, enabling ad-hoc analysis without loading the datasets into a separate database.

The query results are stored in the following Amazon S3 location:

**Query results location:** *s3://careplus-ds/careplus-athena-results/*

**Workflow:**

1. Processed support logs and support tickets are stored in Amazon S3 in Apache Parquet format.
2. AWS Glue crawlers scan their respective S3 prefixes and catalog the datasets.
3. The crawlers create or update table metadata in the AWS Glue Data Catalog.
4. Amazon Athena uses the cataloged tables to execute SQL queries.
5. Query results are saved to s3://careplus-ds/careplus-athena-results/ for access and further analysis.

**Data flow:**

- **Support Logs:** `Amazon S3 (support-logs/processed/) → AWS Glue Crawler (crawl_support_logs) → Athena Table (support_logs_processed)`
- **Support Tickets:** `Amazon S3 (support-tickets/processed/) → AWS Glue Crawler (crawl_support_tickets) → Athena Table (support_tickets_processed)`
- **Query Results:** `Amazon Athena → Amazon S3 (careplus-athena-results/)`

### 6.5 Data Warehousing – Amazon Redshift Serverless

Amazon Redshift Serverless is used as the data warehouse for storing and querying the processed support logs and support tickets for analytical reporting.

A database named *careplus-db* was created in Amazon Redshift, with the *support_logs* and *support_tickets* tables created under the *public* schema to store the corresponding datasets.

To automate data loading, S3 event notifications are configured to trigger the respective AWS Lambda functions whenever new files arrive in the processed-data locations.

**Incremental data-loading workflows:**

- **Support Logs:** The S3 event notification *trigger_incremental_data_logs* invokes the Lambda function *Incremental_data_load_logs* when new files arrive in *support-logs/processed/*. The function loads the new data into the *public.support_logs* table in Amazon Redshift.
- **Support Tickets:** The S3 event notification *trigger_incremental_data_tickets* invokes the Lambda function *Incremental_data_load_tickets* when new files arrive in *support-tickets/processed/*. The function loads the new data into the *public.support_tickets* table in Amazon Redshift.

**Data flow:**

- **Support Logs:** `Amazon S3 (support-logs/processed/) → S3 Event Notification (trigger_incremental_data_logs) → Lambda (Incremental_data_load_logs) → Amazon Redshift (public.support_logs)`
- **Support Tickets:** `Amazon S3 (support-tickets/processed/) → S3 Event Notification (trigger_incremental_data_tickets) → Lambda (Incremental_data_load_tickets) → Amazon Redshift (public.support_tickets)`

### 6.6 Business Intelligence and Visualization – Power BI

Power BI connects to Amazon Redshift Serverless to visualize the CarePlus support ticket and support log datasets. 
Two dashboards were developed: **Careplus Ticket Insights** and **Careplus Support Logs**. These dashboards summarize ticket status, agent workload, issue resolution time, application log activity, CPU utilization, and response performance.

#### A. Careplus Ticket Insights Dashboard

The **Careplus Ticket Insights** dashboard provides an overview of support ticket volume, resolution status, agent workload, and resolution time.

**Key performance indicators (KPIs):**

- **Total Tickets**
- **Resolved Tickets**
- **Open Tickets**
- **Escalated Tickets**
- **Total Agents**
- **Average Interactions**
- **Average Resolution Time**

**Visualizations and insights:**

- **Total Tickets by Channel and Status**
- **Total Tickets by Agent**
- **Average Resolution Minutes by Issue Category**
- **Average Resolution Minutes by Priority**
- **Ticket Details Table**

#### B. Careplus Support Logs Dashboard

The **Careplus Support Logs** dashboard summarizes application log volume, log severity, CPU utilization, and response-time performance. A date selector is provided for reviewing logs by day.

**Key performance indicators (KPIs):**

- **Total Logs**
- **Logged Tickets**
- **Average CPU Utilization**
- **Average Response Time**

**Visualizations and insights:**

- **Average CPU (%) by Timestamp**
- **Total Logs by User Agent**
- **Total Logs by Log Level**
- **Total Logs and Logged Tickets by Response-Time Range**

**Data flow:**

`Amazon Redshift Serverless → Power BI → Careplus Ticket Insights and Careplus – Support Logs Dashboards`

## 7. End-to-End Data Flow

The complete pipeline follows this sequence:

1. The CarePlus System generates support logs and support tickets.
2. Raw datasets are ingested into Amazon S3.
3. AWS Lambda processes support logs, while AWS Glue processes support tickets.
4. Processed datasets are stored in Amazon S3 in Apache Parquet format.
5. Amazon Athena queries the processed datasets for ad-hoc SQL analysis.
6. The processed data also feeds Amazon Redshift Serverless for data warehousing.
7. Power BI connects to Amazon Redshift Serverless to build reports and dashboards.

### Pipeline Summary

**Data ingestion and processing:**

`CarePlus System → Amazon S3 (Raw) → AWS Lambda / AWS Glue → Amazon S3 (Processed – Parquet)`

**Analytical workflow 1 – SQL Analytics:**

`Amazon S3 → Amazon Athena → Ad-hoc SQL Analysis`

**Analytical workflow 2 – Business Intelligence:**

`Amazon S3 → Amazon Redshift Serverless → Power BI → Reports and Dashboards`
